# BIBLIOTHÈQUE DE PATTERNS — TUNNELS DE VENTE
Ce document catalogue les variantes visuelles disponibles pour chaque type de section d'un tunnel de vente. Chaque pattern est un squelette structurel, indépendant du contenu textuel et de la palette de couleurs finale.
**Règle d'usage** (à appliquer par le skill, pas seulement à lire) :
1. Ne jamais utiliser deux fois le même pattern pour le même type de section dans un même tunnel.
2. Ne jamais enchaîner deux sections adjacentes qui partagent le même traitement de conteneur (ex : deux sections "carte ombrée" à la suite). Alterner avec un pattern "plat" ou "sans carte" entre deux patterns "carte".
3. Pour les sections de type split (texte/image), respecter l'alternance gauche-droite stricte définie dans le skill layout — indépendamment du pattern choisi.
4. La densité de contenu doit guider le choix : un texte court va vers un pattern numéroté/plat, un texte long va vers un pattern liste/carte avec espacement généreux.

## HERO
### `hero-split-stats-search-b2b`
**Layout** : Split 50/50, nav légère en haut (logo + 2 liens).
**Structure** : Titre + sous-titre + 2 CTA (primaire/secondaire) + 3 stats alignées horizontalement en bas de colonne gauche. Colonne droite : image/illustration.
**Densité** : Riche. **Différenciateur** : preuve sociale chiffrée intégrée au hero.
**Mobile** : empilement vertical, stats en ligne ou 3 colonnes serrées.
### `hero-video-centered-funnel`
**Layout** : Empilé centré, vidéo en bloc médian.
**Structure** : Titre + paragraphe + CTA → lecteur vidéo → sous-titre  → liste à puces avec pourcentages(.
**Densité** : Moyenne. **Différenciateur** : lecteur vidéo intégré, logique "regarde puis convertis".
**Mobile** : vidéo passe en full-width, liste reste empilée.
### `hero-centered-nav-glow`
**Layout** : Empilé centré pur .
**Structure** : Badge/tag → titre → paragraphe → 1 CTA. Ambiance glow/gradient en fond.
**Densité** : Légère. **Différenciateur** : le plus épuré, mise sur la typographie et l'espace négatif.
**Mobile** : nav devient hamburger, badge et titre se réduisent.

## PROBLÈME / AGITATION *(nouveau)*
### `problem-split-pain-checklist`
**Layout** : Split 50/50. Colonne texte : titre + liste de symptômes/douleurs cochés en rouge/orange (✗). Colonne image : illustration de la situation "avant".
**Structure** : Titre accusateur ("Tu reconnais ce scénario ?") → 4-5 lignes de douleur avec icône croix → micro-CTA transition vers section suivante.
**Densité** : Moyenne. **Différenciateur** : utilise la couleur d'alerte (rouge/orange) sur un fond par ailleurs neutre — seule section du tunnel à le faire, pour créer un contraste émotionnel volontaire.
**Mobile** : image au-dessus, liste en dessous.
### `problem-centered-quote-stat`
**Layout** : Empilé centré, sans split.
**Structure** : Titre court → une statistique choc en très grand format (ex : "73% des entrepreneurs...") → phrase d'agitation en dessous → transition vers la solution.
**Densité** : Légère. **Différenciateur** : un seul chiffre choc sert d'ancre visuelle unique, pas de liste.
**Mobile** : identique, tailles réduites.
### `problem-cards-before-comparison`
**Layout** : Grille 2 colonnes type "avant / après" inversé (on montre juste l'avant, en 2-3 cartes de douleur).
**Structure** : Titre → 3 cartes plates (sans ombre) listant chacune un point de friction → ligne de transition textuelle.
**Densité** : Légère à moyenne. **Différenciateur** : design volontairement plus terne/désaturé que le reste du tunnel pour symboliser le problème, avant que les sections suivantes "réactivent" la couleur.
**Mobile** : cartes empilées.

## FONCTIONNEMENT / ÉTAPES (PROCESS)
### `process-grid-numbered-rich`
**Layout** : Grille 2x2, plat (sans carte visible).
**Structure** : 4 blocs avec numéro géant en fond (effet watermark) + titre + liste à puces détaillée.
**Densité** : Riche. **Différenciateur** : hybride process + features, chaque étape contient un mini-bloc de contenu complet.
### `process-timeline-vertical-circles`
**Layout** : Colonne unique avec ligne de connexion verticale (timeline).
**Structure** : 5 étapes, chacune avec numéro en pastille ronde + titre + description courte entre parenthèses.
**Densité** : Moyenne. **Différenciateur** : vraie timeline séquentielle, ligne connectrice visible entre les étapes — idéal pour un parcours chronologique explicite.
### `process-faq-numbered-hybrid`
**Layout** : Colonne unique, questions-réponses numérotées.
**Structure** : Question en gras précédée d'un numéro → réponse détaillée en dessous, dans un style "ça va lever vos objections".
**Densité** : Riche. **Différenciateur** : fusion process + FAQ, rassure tout en structurant la lecture comme un guide étape par étape.
### `process-horizontal-steps-arrow` *(repris des bénéfices, généralisé ici)*
**Layout** : Rangée horizontale de 4 étapes liées par des flèches.
**Structure** : Icône/numéro → titre court → description d'une ligne, répété 4 fois avec connecteurs visuels.
**Densité** : Légère. **Différenciateur** : lecture en flux, le seul pattern de "fonctionnement" sans aucune verticalité.
**Mobile** : passe en colonne, flèches deviennent séparateurs.

## BÉNÉFICES
### `benefits-grid-numbered-flat`
**Layout** : Grille 2 colonnes, plat, sans carte ni ombre.
**Structure** : Numéro en pastille + texte très court (1-2 mots), suivi d'un bloc CTA + bénéfices secondaires en pastilles.
**Densité** : Très légère. **Différenciateur** : numéros géants décoratifs façon "programme/checklist".
### `benefits-cards-4-shadow-longtext`
**Layout** : Grille 2x2, cartes ombrées, fond blanc sur fond gris clair.
**Structure** : Titre de carte en majuscules + 2 lignes de description, bloc "présentation de l'expert" en footer de section.
**Densité** : Riche. **Différenciateur** : le seul pattern bénéfices qui intègre une preuve d'autorité (bloc expert) directement dans la section.
### `benefits-horizontal-steps-arrow`
**Layout** : Rangée horizontale 4 étapes avec flèches.
**Structure** : Identique au process horizontal, mais recadré bénéfices ("Start → We provide → Process → Result").
**Densité** : Légère. **Différenciateur** : présente les bénéfices comme un flux logique plutôt qu'une liste statique.
### `benefits-cards-6-shadow-classic`
**Layout** : Grille 3x2, cartes ombrées classiques.
**Structure** : Titre court en gras + description d'une ligne, répété 6 fois, CTA en footer.
**Densité** : Moyenne. **Différenciateur** : le plus "corporate"/neutre, volume d'information le plus élevé sans surcharge.

## PREUVE SOCIALE / LOGOS *(nouveau)*
### `trustbar-logos-marquee`
**Layout** : Rangée horizontale unique, défilement infini (marquee) ou statique de logos clients/médias.
**Structure** : Micro-titre ("Ils nous font confiance") → rangée de 5-8 logos en niveaux de gris, qui s'illuminent en couleur au survol.
**Densité** : Très légère. **Différenciateur** : seul pattern du tunnel basé entièrement sur des logos, aucun texte explicatif.
**Mobile** : défilement tactile horizontal ou wrap en 2 lignes.
### `trustbar-stats-inline-no-card`
**Layout** : Rangée horizontale 1x3 ou 1x4, sans carte (texte brut sur fond).
**Structure** : Chiffre clé + label, répété, sans logos — orienté "preuve par les chiffres" plutôt que par les marques.
**Densité** : Légère. **Différenciateur** : équivalent du `stats-bar-horizontal-no-card` mais positionné tôt dans le tunnel, juste après le hero.
### `trustbar-press-quote-strip`
**Layout** : Bande horizontale fine, citation courte attribuée à un média/influenceur entre les logos.
**Structure** : Logo média → courte citation de validation → logo média suivant, en alternance.
**Densité** : Légère. **Différenciateur** : mélange logos et citations dans la même bande, format le plus "éditorial".

## OFFRE + PRIX + GARANTIE *(nouveau)*
### `pricing-single-card-spotlight`
**Layout** : Une seule carte centrée, large, mise en lumière par un glow d'accent.
**Structure** : Titre de l'offre → prix barré + prix final → liste de ce qui est inclus (checkmarks) → CTA pleine largeur → mention garantie sous le bouton (badge avec icône bouclier).
**Densité** : Riche mais concentrée. **Différenciateur** : un seul choix, aucune comparaison — réduit la charge de décision, adapté à une offre unique premium.
**Mobile** : carte pleine largeur, glow réduit en intensité.
### `pricing-comparison-3tiers`
**Layout** : Grille 3 colonnes, carte du milieu surélevée/agrandie (effet "populaire").
**Structure** : 3 cartes prix côte à côte, badge "Populaire" sur la centrale, liste de fonctionnalités avec checkmarks/croix selon le tier, CTA par carte.
**Densité** : Riche. **Différenciateur** : structure de comparaison classique, utile si plusieurs offres existent réellement.
**Mobile** : cartes empilées, carte populaire en premier.
### `pricing-split-guarantee-emphasis`
**Layout** : Split 50/50. Colonne gauche : détail de l'offre et du prix. Colonne droite : bloc garantie visuellement dominant (icône large, texte rassurant, durée de la garantie en gros chiffre).
**Structure** : Prix + inclus à gauche, garantie "sans risque" mise en scène à droite comme argument à part entière, pas en petite mention.
**Densité** : Moyenne. **Différenciateur** : la garantie devient un bloc visuel de même poids que le prix — utile quand l'objection principale est la peur du risque.
**Mobile** : empilement, garantie reste visible avant le CTA final.

## FAQ
### `faq-accordion-search`
**Layout** : Colonne unique, Q/R en accordéon, barre de recherche en pied de section.
**Structure** : Titre → liste de Q/R dépliées par défaut ou en accordéon → champ de recherche pour filtrer.
**Densité** : Riche. **Différenciateur** : fonctionnalité de recherche intégrée.
### `faq-sandwich-double-cta`
**Layout** : Colonne unique, contenu structuré en "sandwich".
**Structure** : Bloc de questions → CTA intermédiaire ("Encore des questions ?") → répétition/poursuite du contenu → second CTA.
**Densité** : Riche. **Différenciateur** : double point de conversion au sein même de la FAQ.
### `faq-hub-grid-links`
**Layout** : Grille 2 colonnes, questions seules (sans réponse visible).
**Structure** : Liste de questions cliquables menant à une réponse ou une page dédiée, liens annexes ("voir toutes les FAQ").
**Densité** : Légère. **Différenciateur** : fonctionne comme un hub de navigation plutôt qu'un contenu direct.
### `faq-grid-intro-search`
**Layout** : Grille 2 colonnes + paragraphe d'intro + recherche.
**Structure** : Intro contextuelle → grille de questions avec tirets → bloc "pas trouvé votre réponse" avec CTA expert → recherche.
**Densité** : Moyenne. **Différenciateur** : combine intro narrative, grille et recherche — le plus complet fonctionnellement.

## TÉMOIGNAGES
### `testimonials-3cards-grid`
**Layout** : Grille 3 colonnes égales, cartes ombrées légères.
**Structure** : Nom + poste + témoignage, répété 3 fois, CTA en footer.
**Densité** : Légère. **Différenciateur** : le plus classique et neutre, base de référence.
### `testimonials-2x2-stars-date`
**Layout** : Grille 2x2, cartes avec ombre plus marquée.
**Structure** : Nom + notation étoiles + témoignage + date, répété 4 fois, pas de CTA (section pure preuve sociale).
**Densité** : Moyenne. **Différenciateur** : notation et date façon avis vérifié (style marketplace).
### `testimonials-list-quotes`
**Layout** : Colonne unique, sans carte, citations pures.
**Structure** : Sous-titre conversationnel long → liste de citations entre guillemets avec nom en gras → CTA final.
**Densité** : Riche. **Différenciateur** : le plus textuel, mise sur l'authenticité du récit plutôt que la structure visuelle.
### `testimonials-carousel-video` *(nouveau)*
**Layout** : Carrousel horizontal défilant, une carte visible à la fois (ou 1.5 sur desktop).
**Structure** : Vignette vidéo/photo du client → citation courte en overlay → flèches ou points de navigation.
**Densité** : Légère par carte, mais volume total élevé. **Différenciateur** : seul pattern interactif/navigable de la catégorie, adapté si tu as des témoignages vidéo.
**Mobile** : swipe tactile natif.

## STATS
### `stats-cards-4-suffix-badge`
**Layout** : Grille 2x2, cartes ombrées.
**Structure** : Badge d'intro → 4 cartes avec chiffre + suffixe (K, +) + label.
**Densité** : Légère. **Différenciateur** : badge d'intro comme point d'entrée.
### `stats-cards-4-percent-icons`
**Layout** : Grille 2x2, cartes ombrées.
**Structure** : Identique en structure, mais chiffres en pourcentages/étoiles plutôt qu'en volumes.
**Densité** : Légère. **Différenciateur** : orienté "résultats/impact" plutôt que "volume/échelle".
### `stats-bar-horizontal-no-card`
**Layout** : Rangée 1x4, sans carte, suivie d'un bloc narratif (valeurs/mission).
**Structure** : 4 chiffres alignés horizontalement → section "valeurs" en dessous avec titre et paragraphe.
**Densité** : Légère + bloc narratif. **Différenciateur** : seul pattern stats qui enchaîne directement sur du contenu éditorial, style "rapport d'entreprise".

## CTA FINAL *(nouveau)*
### `cta-final-centered-urgency`
**Layout** : Empilé centré, pleine largeur, fond contrasté (souvent couleur d'accent inversée).
**Structure** : Titre d'urgence court → 1 ligne de réassurance → CTA unique très large → mention de rareté/délai sous le bouton.
**Densité** : Très légère. **Différenciateur** : la section la plus minimaliste du tunnel, volontairement — aucune distraction avant la conversion finale.
### `cta-final-split-recap-benefits`
**Layout** : Split 50/50. Gauche : CTA et titre. Droite : récapitulatif visuel des bénéfices clés (mini liste à checkmarks ou mini stats).
**Structure** : Rappelle 3 bénéfices clés en parallèle du bouton, pour ceux qui scrollent vite jusqu'à la fin sans avoir tout lu.
**Densité** : Moyenne. **Différenciateur** : fait office de "résumé exécutif" du tunnel entier, pas juste un bouton.
### `cta-final-glow-countdown`
**Layout** : Empilé centré avec glow d'accent dominant et compte à rebours visible.
**Structure** : Titre → compteur (jours/heures/minutes) → CTA → garantie en petit texte.
**Densité** : Légère. **Différenciateur** : intègre un élément d'urgence temporelle réelle (à utiliser uniquement si l'urgence est authentique, jamais fictive — voir interdits du skill copywriting).

## FOOTER *(nouveau)*
### `footer-minimal-centered`
**Layout** : Empilé centré, une seule ligne.
**Structure** : Logo → liens légaux (mentions, confidentialité) → copyright.
**Densité** : Minimale. **Différenciateur** : le plus discret, adapté à un tunnel court et focalisé conversion.
### `footer-grid-sitemap`
**Layout** : Grille 3-4 colonnes.
**Structure** : Colonne logo/description → colonne liens produit → colonne liens légaux → colonne contact/réseaux sociaux.
**Densité** : Riche. **Différenciateur** : structure de site complet, utile si le tunnel fait partie d'un site plus large.
### `footer-cta-newsletter`
**Layout** : Empilé centré, bloc newsletter en évidence au-dessus du footer classique.
**Structure** : Bloc capture email ("Reste informé") → ligne de séparation → footer minimal en dessous.
**Densité** : Moyenne. **Différenciateur** : transforme le footer en second point de capture, pas juste une zone légale.

## STATUT D'IMPLÉMENTATION (composants React color-aware)
Chaque catégorie ci-dessous est rendue par un `XxxPatterns.tsx` (contenu-seul,
variables `--ff-*`) + un `XxxRenderer` câblé dans `FunnelPreview`, clés alignées
sur `SECTION_PATTERN_VARIANTS` (`lib/ai/generate.ts`).

| Catégorie | Type(s) section | Renderer | Statut |
|---|---|---|---|
| Hero | `hero` | HeroRenderer | ✅ |
| Bénéfices | `benefits` | BenefitsRenderer | ✅ |
| Offre+Prix | `pricing` / `offer` | PricingRenderer | ✅ |
| Témoignages | `testimonials` / `proof` | TestimonialsRenderer | ✅ |
| FAQ | `faq` | FaqRenderer | ✅ |
| CTA final | `cta` | CtaFinalRenderer | ✅ |
| **Stats** | `proof` (pattern `stats-*`) | **StatsRenderer** | ✅ nouveau |
| **Problème/Agitation** | `problem` / `agitation` | **ProblemRenderer** | ✅ nouveau |
| **Process** | `process` | **ProcessRenderer** | ✅ nouveau |
| Logos/Confiance (trustbar) | — (aucun type dédié) | — | ⚠️ voir note |
| Footer | — (composant global `FunnelFooter`) | — | ⚠️ voir note |

**Note trustbar & footer** — Ces deux catégories ne correspondent PAS au système
de patterns par section :
- **Trustbar/Logos** n'a aucun `FunnelSectionType` dédié. La variante
  `trustbar-stats-inline-no-card` est déjà couverte de fait par les patterns
  **Stats** (une section `proof`/stats placée tôt dans le tunnel). Les variantes
  `trustbar-logos-marquee` et `trustbar-press-quote-strip` exigent des ASSETS
  (logos clients/presse) que le produit ne génère pas encore → nécessitent un
  nouveau type de section + gestion d'assets (feature dédiée).
- **Footer** est un composant GLOBAL (`components/funnel/FunnelFooter.tsx`) piloté
  par `funnel.meta`, pas une section à `bullets`/`items`/`pattern`. L'actuel
  correspond à `footer-minimal-centered`. `footer-grid-sitemap` (données de liens)
  et `footer-cta-newsletter` (capture email → wiring leads) demandent une feature
  dédiée, à traiter séparément avec build de validation.

Détection Stats : une section `proof` dont les puces sont chiffrées
(`"12K+ | Clients servis"`) est préservée (pas de conversion en témoignages) via
`looksLikeStatsBullets` dans `generate.ts`, puis rendue par `StatsRenderer`.
